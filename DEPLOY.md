# Развёртывание ТАКТИЛЬНО на RelaxDev

Основной хостинг проекта — российская PaaS-платформа [RelaxDev](https://relaxdev.ru)
(панель проекта: `relaxdev.ru/projects/taktilno`). Деплой — из GitHub-репозитория,
ветка `main`, стек определяется автоматически (Next.js).

## 1. Код в GitHub

```bash
git add -A
git commit -m "Описание изменения"
git push origin main
```

Не коммитьте `.env` с реальными паролями (он в `.gitignore`). Все настройки —
только через переменные окружения в панели RelaxDev.

## 2. Проект на RelaxDev

1. Зайдите на relaxdev.ru через GitHub-аккаунт, на котором лежит репозиторий.
2. «Добавить проект» → выберите репозиторий `taktilno` → ветка `main`.
3. Оставьте включённым «Автоопределение стека» (Dockerfile не нужен).
4. Включите «Автодеплой», чтобы `push` в `main` сам выкатывался в продакшн.
5. «Деплой». После первой успешной сборки сайт доступен на системном домене
   вида `https://taktilno.relaxdev.ru` (точное имя — в панели проекта).

## 3. База данных

1. В панели проекта откройте раздел «База данных» → создайте PostgreSQL.
   Платформа сама подставит `DATABASE_URL` в переменные окружения проекта.
2. Ничего накатывать вручную не нужно: при первом запросе приложение само создаёт
   таблицы (`CREATE TABLE IF NOT EXISTS`) и докладывает новые колонки (`ALTER TABLE ...
   ADD COLUMN IF NOT EXISTS`), а если каталог пуст — создаёт демо-товары.
3. Если хотите применить схему через `drizzle-kit` вручную: раздел «Доступ к БД» →
   откройте внешний порт и добавьте свой IP в белый список (узнать IP: `curl ifconfig.me`),
   затем локально:
   ```bash
   # временно впишите внешний URL базы в drizzle.config.json, затем:
   npx drizzle-kit push --force
   # верните локальный URL обратно
   ```

## 4. Переменные окружения

Проект → Настройки → Переменные окружения (формат «Ключ — Значение»), затем редеплой:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | подставляется автоматически при создании PostgreSQL |
| `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен` (системный `*.relaxdev.ru` или свой; см. раздел 5) |
| `ADMIN_PASSWORD` | ваш надёжный пароль админки |
| `ADMIN_SECRET` | любая длинная случайная строка (подпись cookie администратора) |
| `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` | обязательные реквизиты магазина ЮKassa |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | когда появятся |
| `POCHTA_FROM_INDEX` | `350000` (индекс отправления в Краснодаре; остальные `POCHTA_*` — по умолчанию из `.env.example`) |
| `POCHTA_TOKEN` / `POCHTA_KEY` | только если есть договор с Почтой (API «Отправка»); иначе не задавайте |

> `NEXT_PUBLIC_*` вшиваются в клиентский бандл во время сборки — после их изменения
> обязательно запускайте редеплой. Остальные переменные читаются на сервере в рантайме.

## 5. Домен

- Системный домен `{name}.relaxdev.ru` работает сразу после первого деплоя.
- Свой домен: вкладка «Домены» → добавьте домен → у регистратора пропишите A-запись
  на IP из панели → «Обновить SSL» (Let's Encrypt выпустится автоматически).
- После привязки домена обновите `NEXT_PUBLIC_SITE_URL` и сделайте редеплой,
  а в ЛК ЮKassa укажите webhook на финальный домен (см. «Оплата ЮKassa»).

## 6. Превью-окружения (проверка веток до продакшна)

Каждую фича-ветку можно проверить на отдельном адресе, не трогая прод:

1. Вкладка «Окружения» → выберите ветку → «Создать».
2. Через 1–3 минуты превью доступно на `проект-git-ветка.preview.relaxdev.ru`
   (HTTPS включён, от поисковиков закрыто).
3. Режим базы данных для веток с миграциями — **«Только схема»**
   (отдельная база со структурой продакшна; приложение само накатит изменения
   и посеет демо-каталог). Не используйте «Как в продакшне» для таких веток.
4. Превью наследует переменные продакшна. Для тестовых заказов скопируйте набор
   («Скопировать из продакшна») и подставьте **тестовые** ключи ЮKassa.
5. Проверенную ветку влейте в `main` (кнопка слияния в панели работает для GitHub) —
   автодеплой обновит продакшн сам.

Превью живёт 72 часа (продлевается пересборкой), лимит — 5 превью на проект.

## Важно про RelaxDev

- Сборке доступ к БД **не нужен**: все страницы рендерятся динамически, `next build`
  проходит без `DATABASE_URL` (проверено). Тумблер «Сборка с доступом к БД» не включайте.
- Файлы, загруженные через админку, хранятся в PostgreSQL — переживают любые редеплои.
- Проверка живости: `GET /api/health` (возвращает `{ ok: true }` + пинг базы).
- Логи приложения — в панели в реальном времени; откат — кнопка «Откатить» в истории деплоев.
- Порт задавать не нужно: `next start` сам слушает `PORT` от платформы.

## Замена изображений на свои

Всё делается в админке, смотрите раздел «Админ-панель» в README.

1. `/admin/login` → пароль администратора.
2. Товары → выберите товар → блок «Изображения».
3. Выберите тип загрузки (Главное / Спереди / Сбоку / Сзади / Сверху / Детали / В руке / Lifestyle / Кадр 360°) → «Выбрать файлы» (можно несколько сразу).
4. Кнопка «Сделать главным» — это фото появится в каталоге, хитах, hero и корзине.
5. Порядок — стрелки «← / →»; первое в списке идёт первым в галерее.
6. Картинки главной, категорий, блока про тактильность и этапов — в «Настройки сайта» (везде есть кнопка «Загрузить»).

### Требования к фото

- Квадрат 1:1, минимум 1200×1200 (лучше 1600×1600) — вёрстку не сломают любые пропорции.
- JPG или WebP, до ~1 МБ. Сжать: squoosh.app.
- Тёмный фон продукта ляжет в дизайн лучше всего, но это необязательно.
- Для 360°: 12–24 кадра поворота, тип «Кадр 360°», в правильном порядке.

## Оплата ЮKassa

1. Регистрация магазина на yookassa.ru → ЛК → Интеграция → API-ключи → получить `shopId` и секретный ключ.
2. В ЛК задайте URL для уведомлений: `https://ваш-домен/api/payments/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.
3. Добавьте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в переменные окружения RelaxDev → редеплой.
4. Сделайте тестовый заказ тестовой картой из документации ЮKassa.

ЮKassa — единственный способ оплаты. Пока ключи не заданы, кнопка оформления отключена, а API заказов отклоняет запрос. В чеке каждый товар передаётся отдельной позицией, платная доставка — отдельной услугой.

## Почта России

Интеграция работает из коробки, без договора с Почтой:

- **Тариф и сроки** — живой расчёт через публичные API `tariff.pochta.ru` и `delivery.pochta.ru`
  по индексу получателя (индекс — обязательное поле чекаута для Почты).
- **Гибридная цена** — ниже 2 000 ₽ покупатель платит реальный тариф Почты, от 2 000 ₽ — бесплатно.
  Итог всегда пересчитывается на сервере; если API Почты недоступны, заказ не блокируется —
  применяется стандартный тариф 300 ₽ (fallback).
- **Трек-номера** — после отправки введите номер с чека в карточке заказа (`/admin/orders/[id]`),
  покупатель увидит ссылку на отслеживание на странице своего заказа.
- **Калькулятор** — виджет на странице `/delivery`, проверка тарифа — в админке
  «Настройки сайта» → «Почта России».

Настройки через переменные окружения (все необязательные, значения по умолчанию в `.env.example`):

| Переменная | Назначение |
| --- | --- |
| `POCHTA_FROM_INDEX` | Индекс пункта отправления (Краснодар). Уточните свой в отделении Почты |
| `POCHTA_TARIFF_OBJECT` | `23030` — «Посылка онлайн» (по умолчанию, публичный тариф без договора); `27030` — «Посылка стандарт»; `47030` — «1 класс». Если объект недоступен, код сам перебирает запасные |
| `POCHTA_DEFAULT_ITEM_WEIGHT_G` / `POCHTA_PACKAGING_WEIGHT_G` | Вес изделия по умолчанию и упаковки, г (у каждого товара свой вес — поле «Вес для доставки» в карточке товара) |
| `POCHTA_TOKEN` / `POCHTA_KEY` | API «Отправка» по договору: токен и ключ из ЛК `otpravka.pochta.ru` → Настройки → API. Дают тарифы со скидкой по договору и нормализацию адресов; без них используется публичный тариф |

### Чеклист публикации интеграции

1. Создайте превью из ветки с интеграцией («Окружения» → ветка → «Создать», режим БД
   «Только схема») либо выкатите ветку в прод и проверяйте там.
2. Задайте `POCHTA_FROM_INDEX` в переменных окружения → редеплой.
3. Проверьте вес товаров в админке (Товары → «Вес для доставки, г»).
4. Откройте `/delivery` — калькулятор должен посчитать тариф для индекса `101000`
   (не fallback 300 ₽ — под суммой не должно быть пометки про стандартный тариф).
5. В админке «Настройки сайта» → «Почта России» нажмите «Проверить тариф Почты».
6. Сделайте тестовый заказ с доставкой Почтой на индекс `101000` (сумма ниже 2 000 ₽ —
   в заказе должен быть тариф Почты, а не 300 ₽) и заказ от 2 000 ₽ (должно быть бесплатно).
   На превью используйте тестовые ключи ЮKassa (см. раздел 6, п. 4).
7. В карточке тестового заказа сохраните трек-номер `12345678901234` — убедитесь, что ссылка
   на отслеживание открывается. Затем удалите тестовый заказ.
8. Если есть договор с Почтой: добавьте `POCHTA_TOKEN`/`POCHTA_KEY` → редеплой → повторите п. 5
   (источник должен стать «API „Отправка“ по договору»).

## Telegram-уведомления

1. В Telegram: @BotFather → /newbot → токен → `TELEGRAM_BOT_TOKEN`.
2. Напишите боту что угодно, затем узнайте id чата (@userinfobot или API) → `TELEGRAM_CHAT_ID`.
3. Добавьте переменные в RelaxDev → редеплой. Тест: сделайте заказ.

## Альтернативы (если RelaxDev не подходит)

**Vercel:** импорт репозитория, те же переменные окружения
(`DATABASE_URL` — например, строка Neon), домен в Settings → Domains.
Нюанс: лимит тела запроса ~4.5 МБ — фото в админку грузите файлами до ~4 МБ.

**VPS:**
```bash
# Ubuntu 22+, Node.js 20+, PostgreSQL 15+
git clone <репозиторий> && cd taktilno
npm ci
cp .env.example .env && nano .env   # заполнить
npx drizzle-kit push --force
npm run build
npm i -g pm2 && pm2 start npm --name taktilno -- start && pm2 save && pm2 startup
# Nginx: proxy_pass на 127.0.0.1:3000; SSL: certbot --nginx
```
